## 原则

北极星目标：从行为、思考层、思想层、发散思维与联想、线性生命链、记忆结构与检索六个维度，实现拟人化的 bot 生命活动与跨平台社交交互。所有路线图内容都是这个目标的分层落地。

v1 所有新功能都应保留观察者与 owner-only 的边界：不注册账号、不发帖、不保存网页原文；跨平台社交表达为 v1.5+ 方向。“生活感”来自五个维度：连续性、节奏、关系、意外、可被看见。

## v1.1：低成本高体感

- 今日人格签名（v0.3.0 已落地）：每晚在日记外生成一句“今日签名”，形成可翻看的签名流。
- 旧事新感（v0.3.2 已落地）：夜间复盘随机回看 7/30 天前的短记，生成“后来的我再看这件事”。
- 精力预算：每日漫游有能量上限，低精力时只刷轻内容，高精力才啃 HN/GitHub。
- 随机不出门（v0.3.3 已落地）：按概率跳过当天漫游，但写一条状态快照，允许 bot 偶尔躺平。
- 时段模式（v0.3.4 已落地）：早高峰/午休/深夜使用不同内容偏好与语气。
- 轻接触 peek（v0.3.5 已落地）：高频低成本的“路过”动作，只更新状态快照不产短记；正式漫游 + peek + 复盘的频率模型见 `docs/design.md`。
- 灵感抽屉（v0.3.6 已落地）：LLM 把“也许有用但今天不展开”的东西放进 wishlist，定期翻出来评估。
- 月历热力图（v0.3.0 已落地）：WebUI 用贡献图样式展示每天漫游/日记/分享密度。
- 状态小卡片（v0.3.0 已落地）：Dashboard 展示当前 persona 的心情、精力、今天在看什么。
- WebUI 视觉优化（v0.3.1 已落地）：统一排版、空态、错误态、加载态与移动端适配，保持零前端依赖。
- 时间轴（v0.3.7 已落地）：WebUI 按时间倒序混排短记、日记、分享与状态变化。
- 工程基线（同批）：预算/重试/崩溃（含 db 事务化前置改造）、时区、变更账本+回收站、安全基线、WebUI 美化、同人格单 SQL 租约；细节见 `docs/features.md` L1-11 至 L1-16（已落地：时区 v0.2.5、预算/重试/崩溃 v0.2.6、变更账本+回收站 v0.2.7、安全基线 v0.2.8、同人格单 SQL 租约 v0.2.9）。

## v2：结构性能力

- 实体与关系图：新增 `entities` 与短记关联，记录“我认识的人/项目/社区”及印象变化（分层维度模型见 `docs/design.md`）。
- 关注对象：主人配置持续关注名单（博客、GitHub 用户/项目、RSS），形成追更感。
- 故地重游：定期 revisit 收藏链接或项目，写“后来呢”。
- 记忆温度：短记带热度与遗忘曲线，冷记忆淡出，被重新提及时“想起来”。
- 月度/年度回顾：自动生成“这个月漫游 N 次、兴趣从 X 变成 Y、有几天没出门”。
- 时间胶囊：封存一条短记，30 天后解锁并让 LLM 以当时人格回信。
- 分享沉默率：分享 gate 增加概率性“今天不想说”，避免每次都机械表达。
- 季度自我评估：基于兴趣与情绪轨迹生成长期人格总结。

> 注：以下早期“方向”条目已按功能分层重新归位，保留仅作历史说明；落地一律以 `docs/features.md` 为准：LLM 自主行动排期 → L1.5，统一记忆库 → L2，可被看见 → L1/L1.5/L2 分档，自主生活内核 → L1.5 + L2。

## 方向（未排期）：LLM 自主行动排期

这是“连续性”功能想要自然化的一条候选路径，目前只作为方向记录，不承诺落地。

- 原则：LLM 决定“做什么”，系统决定“何时做”。LLM 只产出行动清单与偏好时间窗，精确排期由调度器映射。
- 封闭动作词表：`browse / revisit / signature / diary / share / rest / surprise / memory_review`，未知动作拒绝并回退默认计划。
- 反馈闭环：新增 `life_plans` 与 `action_log`，昨天执行结果进入今天的生活摘要，产生“昨天没出门今天补一次”“回看 30 天前那条”这类连续性。
- 系统硬约束：睡眠窗口、精力 gate、每日行动上限、动作前置条件（如 revisit/signature 需要当天有 browse 素材）、LLM 失败回退固定计划。
- 落地顺序：先支持 `browse / rest / signature / revisit` 四个动作与 `/life_plan` 查看命令，跑通后再扩展。

## 方向（未排期）：意外波动

- 意外由 `serendipity_level` 驱动，而非固定概率：均值回归 + 饥饿度 + 状态调制 + 随机噪声。
- 强度分级：micro（冷知识/换话题）、meso（漂流瓶/陌生主题半日）、macro（每月出走日）。
- `surprise` 作为 action 进入计划，但触发频率由系统模型决定，LLM 只决定内容（模型见 `docs/design.md`）。

## 方向（未排期）：可被看见

- 三档落地：零迁移的状态卡/月历热力图/时间轴；需要加列的今日签名与计划卡；等 v2 数据模型的 serendipity 曲线与实体关系图。
- 全部走 `register_web_api`，WebUI 保持 vanilla HTML/CSS/JS；详细计划见 `docs/design.md`。

## 方向（未排期）：统一记忆库

- 由记忆宿主插件持有统一逻辑库，提供版本化公开 API；本插件经 `LifeMemoryAdapter` 读写，本地 SQLite 降级为缓存。
- 多平台同人格通过 `persona_id` 分区键、`seen_platform/entity_platform` 维度与 `same_as` 身份合并实现。
- v2 引入 `LifeMemoryAdapter` 并把统一库切为权威，不经过 v1.1 前置收敛；架构见 `docs/design.md`。

## 架构演进：硬依赖

- v2 起，ESM 与统一记忆宿主（engram_core 或未来 life-chain）为硬依赖；能力探测只用于版本诊断，不做功能开关。
- 本地 SQLite 从权威存储降级为缓存；实体/关系/想法/回忆以统一库为权威。
- 允许对两个插件做大规模架构级变动：精力真实消费与持久化、统一记忆 API、生命链事件流、跨平台身份解析。
- 兼容前提：kazamisama 全部 AstrBot 插件保持整体兼容，同时不吝啬对家族内插件的改动（重构、新增共享层、改契约均可），以版本化契约、适配层隔离与整族协调升级兜底（见 `docs/requirements.md`）。
- v1 保留静默降级作为过渡，但不作为 v2 目标。

## 工程基线（已确认）

- 预算可配置（v0.2.6 已落地）：LLM 调用次数与 token 量默认无上限；多轮联想每轮候选上限 5；失败重试上限 3，耗尽报 error，不生成伪造内容。
- 崩溃语义（v0.2.6 已落地）：run 级暂存，崩溃丢弃未提交数据、不污染档案，宁缺毋滥并报 error。
- 时区（v0.2.5 已落地）：`timezone` 可配置，默认 `Asia/Shanghai`；睡眠窗口与“今日”边界按 persona 本地时间。
- 并发：不同人格不同记忆库；人格经历严格线性，事件链单写者；同人格用槽位唯一键 + 幂等 + 任务租约保证串行化。
- 冷启动：新人格自由探索 + owner 手动干预，达到最小素材量后进入常规节奏。
- 人格演化：不可变内核 + 可演化层 + 版本化 center state + owner 确认与回滚；提示词版本化是工程版本，不是人格自演化。

## 方向（未排期）：内隐思考层

- 记忆分观察/表达/中心三层；中心层（center state + private thoughts）承载人格未说出口的思考，作为人格一致性的锚点。
- 每晚内省提炼 center state，思考事件带来源与版本历史；模型见 `docs/design.md`。

## 方向（未排期）：联想召回

- 语境 → 分层 cue 生成（词法/实体、图扩散、模板、LLM 补全、HyDE 回退）→ 多路召回 → 带回来源的唤醒。
- 召回受人格一致性、注入上限、相关性门槛、时效与来源标注约束，防止人格割裂、语境偏移与事实错位；模型见 `docs/design.md`。
- 多轮联想：正常模式最多 2 轮（5→3 递减），带访问集去重与收敛判断；brainstorm 模式 3-5 轮，只进 WebUI 灵感视图不注入对话。
- 拟人化机制：会话级激活、多尺度记忆金字塔、模糊/具象化、familiarity/recall 双阈值的既视感（见 `docs/design.md`）。

## 方向（未排期）：自主生活内核

- LLM 可自主更改生活数据/计划/记忆（类型化动作 + 权限边界），按事件链自主排期，支持回收站与回滚。
- 记忆连续性原则：“发生过的一定可查”：事件链为事实账本，context_refs 维持思维连续性，夜间压缩 + 检查点防漂移；模型见 `docs/design.md`。
- 排期板分层：固定任务（总结/检查点/温度衰减）与可选任务（revisit/surprise 等）分离，LLM 可加/换序/跳过；睡眠窗口、精力与预算始终为系统硬约束。

## 与现有路线图衔接

- 全平台消息事件统一处理的“生命链”：为实体记忆与多平台一致性提供事件底座。
- 群聊入档、记忆编辑/删除、语义召回（FTS5/向量）与 engram_core 联动：补齐记忆闭环。
- ESM 互联网漫游专用信号与后台任务精力语义：让精力预算成为真实约束，见 `docs/requirements.md`。

## 落地顺序建议

与 `docs/features.md` 开发顺序建议保持一致：

1. 工程基线：时区、预算/重试/崩溃（含 db 事务化前置改造）、变更账本/回收站、安全基线、同人格单 SQL 租约。
2. 高体感：今日签名、状态卡、月历热力图；WebUI 美化随状态卡/热力图视图落地后推进。
3. L1 剩余：精力预算（依赖 ESM `consume_energy`，与上游契约同批）、旧事新感、随机不出门、时段模式、peek、灵感抽屉、时间轴。
4. L1.5：事件链（v0.3.8 已落地）→ 排期板（v0.3.9 已落地）→ 自主排期 → 事件链可视化。
5. L2：先对齐 `_PUBLIC_API.md` 并整族协调，再按结构性能力推进。
