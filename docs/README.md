# 文档索引

本目录是 Your Own Life 的文档入口，按“先看工作流，再读现状，最后看方向”的顺序阅读。

| 文档 | 内容 | 什么时候读 |
| --- | --- | --- |
| `AGENTS.md`（仓库根） | 项目开发守则，agent 会话自动加载 | 每次会话开始 |
| `workflow.md` | 开发与发布工作流、Subagent 约束、PowerShell 5.1 中文处理 | 每次改动前 |
| `devlog.md` | 开发日志：每阶段目标、决策、验证与下一步 | 新会话/上下文压缩后 |
| `design.md` | 现状架构、数据流与方向模型 | 理解插件怎么运作、未来方向 |
| `features.md` | 功能分层开发清单：状态/依赖/模块/配置/验收 | 开发前选功能、开发中查验收 |
| `requirements.md` | 上游对接需求、硬依赖与生态兼容约束 | 跨插件改动前 |
| `roadmap.md` | 生活感路线图（v1.1 / v2 / 未排期） | 规划功能时 |
| `consistency.md` | 功能实现与设计目标一致性审计矩阵 | 检查实现是否符合设计时 |

## 阅读顺序建议

1. `workflow.md`：怎么改。
2. `devlog.md`：上次做到哪、下一步是什么。
3. `design.md`：现在是什么样。
4. `features.md`：这层做什么、怎么验收。
5. `requirements.md`：跨插件边界在哪里。
6. `roadmap.md`：要往哪走。

## 关键交叉约束

- 北极星目标：行为/思考层/思想层/发散联想/线性生命链/记忆结构与检索六维度，见 `design.md` 定位与 `roadmap.md` 原则。
- 硬依赖：v2 起 ESM 与统一记忆宿主为硬依赖，本地 SQLite 降级为缓存。
- 生态兼容：kazamisama 全部 AstrBot 插件整体兼容，但兼容不等于冻结；改动放开，契约版本化、整族协调升级。
- 质量门槛：改动前先读源码；每阶段落地后 review + debug + 测试，通过后再推送。
- 安全边界：只改工作区内且纳入 git 的文件；不删改工作区外或无 git 仓库的内容；缺依赖可以安装。
